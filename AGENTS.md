## 1. Что это за проект и зачем

**Рация и радиостанция** по мотивам китайской рации Quansheng UV-K5. Цель — чтобы друзья могли
общаться голосом (push-to-talk, «нажал — говори») с компьютера и с телефона через свой сервер, с
шифрованием, и чтобы это **работало даже на слабой сети (2G, мобильный интернет через VPN)**.

Конечный результат — четыре приложения, которые говорят на одном протоколе и слышат друг друга:

| Приложение | Где код | Что это |
|---|---|---|
| **ПК «Радио»** (станция) | `radio-air-PC/desktop/` (Electron) | Большое приложение: рация + свой сервер эфира + интернет-радио как источник + Telegram-бот управления. `appId ru.radio.air`, productName «Радио». |
| **ПК «Рация»** (виджет) | собирается из `radio-air-PC/` скриптом `pack_walkie.py` | Урезанная «Радио»: только рация + полоска поверх игр, без станционных модулей. `appId ru.radio.walkie`, productName «Рация». |
| **Android «Рация»** | `android/` (Java + WebView), веб-часть из `radio-walkie/web/` | Та же рация в WebView + кнопка PTT поверх приложений, фоновый приём, анонимность, QR-ключи. `applicationId ru.radio.walkie`. |
| **Android «Радиостанция»** | `radio-air/` (Java + WebView) | Своя FM-станция: играет музыку из папки и голос в эфир. `Station-`. Подробно: [`radio-air/README.md`](radio-air/README.md). |

Для кого: для автора ([BuninSil](https://github.com/BuninSil)) и Valex и их друзей. Это
личный проект, не продукт. Пользователь общается по-русски, неформально; пиши комментарии и
документацию по-русски.

## 2. Стек и минимальные версии

**ПК (Electron):**
- Node.js **20+** (CI использует 20).
- Electron `^44.4.3`, electron-builder `^26.15.3`, electron-updater `^6.3.9`.
- Нативная зависимость `uiohook-napi ^1.5.5` (глобальные горячие клавиши), `ws ^8.21.3` (WebSocket-сервер эфира).
- Сборка только под Windows (`--win`, NSIS-установщик). CI: `windows-latest`.
- Python **3.12** — для `pack_walkie.py` (упаковка «Рации») и серверных утилит.
- `ffmpeg` (win64) — нужен только станции «Радио» для ретрансляции интернет-радио. В репозиторий
  **не коммитится**, CI качает его в `radio-air-PC/desktop/vendor/` перед сборкой (см. `.gitignore`).

**Android (обе апки):**
- Gradle Wrapper в каждом модуле (`android/`, `radio-air/`), AGP `8.13.0`.
- JDK: локально **17+**, в CI — **temurin 21**.
- `compileSdk 36`, `targetSdk 36`, `minSdk 26` (Android 8.0+).
- Зависимости: `androidx.activity:1.11.0`, `androidx.core:1.17.0`, `androidx.webkit:1.14.0`,
  `okhttp:4.12.0`, `zxing-android-embedded:4.3.0` (сканер QR).
- Компилируется с `sourceCompatibility/targetCompatibility VERSION_17`.

**Версионирование Android:** `versionCode = 100 + buildNumber`, `versionName = "1.0.${buildNumber}"`,
где `buildNumber = WALKIE_BUILD_NUMBER` (его ставит workflow «Выпустить релиз» = последний релиз + 1)
или `GITHUB_RUN_NUMBER`, иначе `0`.

## 3. Как собрать и запустить с нуля

Проверено — команды рабочие (взяты из README и CI).

### ПК «Радио» (станция, основная dev-сборка)
```bash
cd radio-air-PC/desktop
npm install
npm start            # запустить приложение (electron .)
npm run dist         # собрать NSIS-установщик → radio-air-PC/desktop/dist/Radio-Setup-<версия>.exe
```
Для `npm run dist` нужен ffmpeg в `radio-air-PC/desktop/vendor/ffmpeg.exe` (иначе установщик соберётся
без него и станция не сможет ретранслировать интернет-радио). В CI он качается автоматически.

### ПК «Рация» (виджет)
```bash
cd radio-air-PC
python pack_walkie.py          # собрать исходники рации в release/radio-walkie/ + zip-архив
python pack_walkie.py --build  # то же + собрать установщик release/Walkie-Setup-<версия>.exe (нужен Node.js)
```
`pack_walkie.py` берёт `desktop/main.js`, `desktop/preload.js`, `desktop/hotkeys.js`, `air-server.js`,
`upnp.js` и веб-файлы из `radio-air-PC/js|css|fonts` + `widget.html`, генерирует отдельный
`package.json` (с `walkieOnly: true` и своим каналом обновлений `walkie`), **сканирует всё на секреты
и личные данные** (почта, домашние IP, токены — см. `SECRET_NAMES`/`SECRET_TEXT` в скрипте) и, если
что-то нашёл, архив не создаёт.

> В корне есть **ещё одна** standalone-копия ПК-рации — `radio-walkie/` (своя `main.js`, `package.json`
> на версии `0.1.0`). Её `npm run dist` тоже соберёт рацию, но это **отдельная ветка кода** — см.
> грабли в разделе 7. Основная разработка идёт в `radio-air-PC/`.

### Android «Рация»
```bash
cd android
./gradlew assembleRelease     # → app/build/outputs/apk/release/app-release.apk (без ключа — неподписанный)
```
`preBuild` зависит от задачи `copyWalkieWeb`, которая копирует `../radio-walkie/web` в APK. То есть
**Android всегда берёт веб-рацию из `radio-walkie/web/`, а не из `radio-air-PC/js/`** (!).

### Android «Радиостанция»
```bash
cd radio-air
./gradlew assembleRelease
```

### Тесты
Автотестов в проекте **нет** (ни unit, ни instrumented, ни JS). Проверка — ручная: собрать, запустить,
поговорить в рацию. Для ПК есть отладочные env-переменные `RADIO_DEBUG_PORT` (remote debugging),
`RADIO_USER_DATA` (отдельный профиль), `RADIO_DEBUG_LOG` (лог в файл) — см. `radio-air-PC/desktop/main.js`.

## 5. Архитектура и поток данных

### Общий принцип
Веб-рация — одна и та же страница на всех платформах. На ПК её открывает Electron и даёт ей
`window.radioDesktop` (через `preload.js`); на Android то же делает `bridge.js`. Поэтому логика
подключения, меню, звука — общая, платформа лишь даёт транспорт и нативные фичи.

### Ключевые JS-модули (в `radio-air-PC/js/`, мирроры в `radio-walkie/web/js/`)
- `app.js` — страница **станции** «Радио» (только в radio-air-PC). `transmit()`, `OPUS_ENABLED`.
- `widget.js` — страница **рации** (виджет). PTT, меню, `transmit()`, согласование кодека, статистика.
- `live.js` — ядро эфира: класс `Broadcaster` (передача, захват, DTX-гейт, выбор кодека) и
  `LiveStation` (приём, диспетчеризация типов пакетов, джиттер-статистика).
- `opus.js` — Opus через WebCodecs (`window.OpusVoice`: `Tx`, `Rx`, `Resampler`). Декодер Chromium
  всегда отдаёт 48 кГц → `Resampler` пересчитывает в 16 кГц (FIR + прореживание).
- `codec.js` — IMA ADPCM (4-битный), fallback-кодек.
- `crypto.js` — сквозное шифрование AES-GCM (ключ из фразы через PBKDF2, 200000 итераций),
  `seal/open` пакеты, `AirKeyring` (связка ключей по KID).
- `link.js` — WebSocket-клиент: `tune`/`onair`/`offair`, сообщает серверу поддерживаемые кодеки.
- `worklets/capture.js` — захват микрофона (AudioWorklet), `worklets/player.js` — непрерывный
  проигрыватель эфира (кольцевой буфер, адаптивный пред-буфер, мягкие фейды — чтобы не трещало).
- `stations.js`, `engine.js`, `channel.js`, `privacy.js`, `voice.js`, `look*.js`, `changelog.js`,
  `updater-ui.js`, `pc-panel.js` — каналы/частоты, движок звука, анонимность, искажение голоса,
  темы, чейнджлог, UI обновлений, ПК-панель.

### Протокол эфира (WebSocket `/ws`)
- **Текст (JSON):** `tune`, `onair`, `offair`, `welcome`, `station-on`, `station-off`, `listeners`,
  `codec`.
- **Двоичное (звук):** `4 байта номера станции` + пакет. Звук: **16 кГц, моно, кадры по 40 мс**
  (`LIVE_RATE=16000`, `LIVE_CHUNK=640`).

### Типы звуковых пакетов (первый байт, см. `crypto.js`)
| Байт | Что |
|---|---|
| 0 | PCM (открытый, несжатый — обычно со станции) |
| 1 | PCM шифрованный |
| 4 | ADPCM открытый |
| 5 | ADPCM шифрованный |
| 6 | Opus открытый |
| 7 | Opus шифрованный |

Второй байт — `seq` (счётчик для восстановления потерь). Шифрованный заголовок `SEALED_HEAD=22`:
`[тип][seq][KID 8][IV 12]` + AES-GCM(шифротекст+тег).

### Согласование кодека (важно!)
Кодек выбирает **сервер**. Приёмник в `tune` сообщает, что понимает (`codecs: ["opus"]`). Сервер
шлёт станции `{"type":"codec","codec":"opus"}`, **только когда Opus понимают ВСЕ слушатели** канала —
иначе `"adpcm"`. Старые рации Opus не декодируют, поэтому пока на канале есть хоть одна старая — весь
канал идёт в ADPCM. Старый сервер `codec` не шлёт вообще → всегда ADPCM. Сам звук сервер не разбирает.

### Автообновление
`electron-updater` (ПК) и собственный апдейтер (Android) проверяют релизы и ставят новую версию
(ПК — не во время передачи). Два канала у ПК: станция «Радио» → `latest.yml` (обычный релиз), рация
→ `walkie.yml` (pre-release-тег `vX.Y.Z-walkie.0`). Разделение, чтобы апдейтеры не путали версии.

## 6. CI / GitHub Actions

Репозиторий: **`WalkieWalkie/Walkie_Walkie`** (origin). Workflows в `.github/workflows/`:

| Файл | Что делает | Запуск |
|---|---|---|
| `publish.yml` «Выпустить релиз» | Собирает и **подписывает** Android-APK (рация или станция), создаёт релиз `walkie-v1.0.N` / `station-v1.0.N`. Версия = последний релиз + 1. | Вручную (workflow_dispatch): выбор `app` (walkie/station) + поле `changes` (пункты через `;`). |
| `pc-release.yml` «PC apps» | Собирает установщики «Радио» и «Рация» для Windows из `radio-air-PC`, публикует двумя релизами (station → latest, walkie → pre-release). Качает ffmpeg в vendor. | Push тега `v*` или вручную: `target` (both/station/walkie) + галка `publish`. |
| `android.yml` | Сборка подписанного/неподписанного APK рации в артефакт. | Push/вручную. |
| `release.yml` | Создаёт релиз из ветки `apk-release` (APK + notes.md). | — |
| `station.yml`, `windows.yml` | Старые/вспомогательные сборки станции и Windows-установщика. | — |
| `release-delete.yml` | Удаление релизов. | Вручную. |

**Секреты репозитория (НЕ в коде, НЕ в `.env`):**
- `WALKIE_KEYSTORE_BASE64` — base64 PKCS12-кейстора для подписи Android (`walkie-release.p12`).
- `WALKIE_KEYSTORE_PASSWORD` — пароль к нему.

CI проверяет, что отпечаток ключа =
`E7:DD:C0:8B:94:FE:2D:00:DF:BF:49:26:2E:2F:DA:A5:D0:85:80:1B:D2:DA:8E:8F:42:09:C4:73:51:2C:73:B2`
(иначе телефоны не примут обновление поверх установленной апки). Без секретов релиз не выпустить.
Подробности выпуска — в [`RELEASING.md`](RELEASING.md).

## 7. Текущее состояние

> Обновляй этот раздел после каждой задачи.

**HEAD:** `19c32b1` «Релиз 0.3.14 / рация 1.0.91». Ветка `main`, рабочее дерево чистое.
Версии: ПК 0.3.14, Android рация 1.0.91, станция — своя нумерация.

### Что работает
- Голосовая связь ПК↔ПК↔телефон через сервер эфира (HOST на ПК-станции).
- Шифрование AES-GCM (меню SCR), QR-обмен ключами на Android.
- ПК-рация (виджет) запускается (чинили падение — см. грабли ниже).
- Android: кнопка PTT поверх приложений, фоновый приём, анонимность, искажение голоса.
- Автообновление обоих каналов.
- **Opus-голос (~18 кбит/с)** включён в рации (`widget.js`) с согласованием кодека через сервер —
  на слабой сети не рвётся так, как ADPCM.
- **Статистика связи** на экране рации (меню **16 STAT**): кодек, трафик, потери, обрывы, буфер.

### Что сломано / частично / под вопросом
- **Станция `app.js` всё ещё `OPUS_ENABLED = false`** — станция «Радио» передаёт только ADPCM.
  Opus в станции не доработан/не включён. Рация Opus и шлёт, и принимает; станция Opus **принимает**
  (приёмник в `live.js` декодирует), но **не шлёт**.
- **DTX выключен** (`this.dtx = false` в `live.js`) — гейт тишины рвал речь кусками на телефоне.
  Сейчас передаём непрерывно. Это сознательный откат, не баг (см. грабли).
- Качество звука на очень слабой сети (2G/VPN) — главная незакрытая тема. Было много жалоб
  «хрипит, заикается, рвётся». Opus помог, но «идеально на 2G» ещё не достигнуто.
- **README.md и RELEASING.md ссылаются на СТАРЫЙ репозиторий** `BuninSil/Walkie-Walkie` в ссылках на
  релизы, хотя код публикуется в `WalkieWalkie/Walkie_Walkie` (см. `publish` в package.json). Ссылки
  в доке для людей устарели — не трогал, но имей в виду.
- **`test.txt`** в корне — мусорный файл (содержит «ТЕСТ»). Можно удалить.
- Автотестов нет вообще.

### Как воспроизвести проблему со звуком
Говорить в рацию на телефоне (мобильный интернет + VPN), слушать на ПК-рации или другом телефоне.
Слушать на предмет: хрипа/металлического призвука (ADPCM), заиканий/провалов (потеря пакетов,
джиттер), задержки (глубокий буфер на плохой сети). Статистика (меню 16 STAT) покажет кодек, %
потерь, число обрывов и размер буфера.

## 9. Принятые решения и грабли (чтобы не наступить снова)

### Решения
- **Opus вместо ADPCM** для голоса: ADPCM «хрустит» и ест ~64 кбит/с, Opus даёт чистый голос на
  ~16–18 кбит/с — вчетверо легче для слабой сети. Но включён через согласование (старые рации Opus
  не умеют).
- **Кодек выбирает сервер**, не клиент — чтобы на канале со старой рацией весь канал падал в ADPCM
  автоматически, без ручных настроек.
- **Два канала обновлений** (latest/walkie) — чтобы станция и рация, лежащие в одних релизах,
  не путали версии друг друга.
- **ffmpeg не в git** — большой бинарь, качается в CI. Нужен только станции.
- **Fix-forward стратегия** (по просьбе пользователя): не откатывать коммитами назад, а чинить
  вперёд новой версией. «Сделай через норм релизы, потом повышением версии откатим».

### Грабли (реальные, уже собранные)
- **ДВЕ копии PC-кода.** `radio-air-PC/` (актуальная, 0.3.14) и `radio-walkie/` (standalone, 0.1.0).
  Android собирается из `radio-walkie/web/`, а dev идёт в `radio-air-PC/js/`. `live.js`/`widget.js`
  в walkie-копии — урезанный сабсет (без станционного интернет-радио). `opus.js`/`crypto.js`
  пока идентичны. **Правь обе копии при изменении аудио-ядра.**
- **ПК-рация падала на старте**: `walkieOnly`-сборка не содержит `telegram.js`/`control.js`/`relay.js`
  (их не стейджит `pack_walkie.py`), а `main.js` их `require`-ил на верхнем уровне → «Cannot find
  module». Решение: ленивый require станционных модулей + заглушки `new TelegramBot`/`new ControlServer`
  под `WALKIE_ONLY` (см. `main.js` ~строки 34–36 и объявления `bot`/`control`). `WALKIE_ONLY =
  pkg.walkieOnly === true || process.argv.includes('--walkie-only')`.
- **Opus в низком тоне / с эхом / задержкой** (0.3.11): декодер Chromium отдаёт 48 кГц, а эфир 16 кГц —
  без пересчёта голос втрое ниже и медленнее. Решение — `Resampler` в `opus.js`. Не убирай его.
- **DTX рвал речь** кусками на телефоне (гейт тишины обрезал начало слов) → выключили (`this.dtx=false`).
  Если будешь возвращать — делай мягкий гейт с длинным хвостом и тестируй именно на телефоне.
- **NSIS installer.nsh**: `pack_walkie.py` вырезает ключ `nsis.include` из сборки рации — в её
  staged-дереве этого файла нет, иначе electron-builder падает «cannot find resource». Был также хук
  `customInit`, который **подвешивал установщик** — его убрали совсем (0.3.9). Не возвращай.
- **Egress-прокси** в этом контейнере блокирует `blob.core.windows.net` → артефакты Actions скачать
  в контейнер нельзя. Доставка готовых сборок пользователю — через релизы, не через artifacts.
- **Нет `gh` CLI** в некоторых окружениях агента — для GitHub используй MCP-инструменты `mcp__github__*`
  (через ToolSearch, если не загружены). Проверяй `command -v gh`.

## 10. Внешние сервисы, ключи, переменные окружения

**`.env` не нужен** — для сборки и запуска никаких ключей/токенов задавать не требуется. Поэтому
`.env.example` в репозитории нет (создавать не надо).

- **Ключ подписи Android** — только в CI как секреты `WALKIE_KEYSTORE_BASE64` и
  `WALKIE_KEYSTORE_PASSWORD` (см. раздел 6). Где взять: у владельца репозитория (файл
  `walkie-release.p12`). В код/репозиторий не кладётся никогда.
- **Telegram-бот станции** (`telegram.js`): токен бота вводится в UI станции и хранится в её локальных
  prefs — НЕ в env, НЕ в секретах CI, НЕ в коде. Токен получают у @BotFather. Фича опциональная:
  без токена бот молча не стартует.
- **Отладочные env-переменные ПК** (не секреты): `RADIO_DEBUG_PORT`, `RADIO_USER_DATA`,
  `RADIO_DEBUG_LOG` — см. `radio-air-PC/desktop/main.js`.
- **Сервер эфира — без пароля** по дизайну: кто знает адрес, тот может слушать открытые каналы и
  выходить в эфир. Приватность — только через шифрование SCR (ключ-фраза).

## 11. Стиль кода и правила коммитов

- **Комментарии и документация — по-русски**, по существу, объясняют «почему», а не «что».
- JS: `'use strict'`, 2 пробела, без сборщиков/транспиляции — чистый браузерный JS, грузится
  `<script>`-тегами (порядок в `widget.html`/`index.html` важен).
- Коммиты — по-русски, в повелительном/описательном стиле, с версией для релизных:
  «Релиз 0.3.14 / рация 1.0.91: …», «Хотфикс 0.3.13: …», «Эфир: …». Один коммит — одна смысловая
  правка.
- **Секреты и личные данные в коммиты не попадают** — `pack_walkie.py` их активно сканирует перед
  упаковкой; не обходи эту проверку.
- Не коммить: `node_modules/`, `dist/`, `release/`, `build/` (Android), `*.exe`, `ffmpeg*`,
  `local.properties`, `*.p12/.keystore`, `.env`, логи. Проверено в `.gitignore` каждого модуля.

## 12. Правила для агента

1. **Не задавай вопросов пользователю** — принимай разумные решения сам, фиксируй их здесь.
2. **Fix-forward**: не откатывай назад, чини вперёд новой версией (повышай номер в `package.json` /
   `buildNumber`).
3. При правке аудио-ядра **синхронь обе копии** (`radio-air-PC/js/` и `radio-walkie/web/`).
4. Тестов нет — проверяй руками: собери, запусти, послушай звук. Описывай, что именно проверить.
5. **После каждой завершённой задачи** обнови разделы 7 «Текущее состояние» и 8 «Что делать дальше»
   в этом файле и закоммить это вместе с изменениями кода.
6. Релизы выпускай только по явной просьбе пользователя (через Actions, см. RELEASING.md) — сами
   коммиты в `main` релиз не создают (кроме пуша тега `v*` для ПК).
7. Для доставки сборок пользователю — релизы, не artifacts (прокси блокирует их скачивание).
